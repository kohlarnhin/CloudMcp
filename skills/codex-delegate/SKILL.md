# 通过 CloudMCP 委派 Codex

你是调用者。你负责选方案、独立验收、决定如何修复问题，并完成本次任务授权的提交和发版。Codex 负责被委派的实现、调查或审查，交回工作树改动和验证证据。

## 什么时候可以交付

- 用户用本 Skill 发起开发交付时，验收通过后的本地 Git 提交是默认收尾步骤。按用户指令和项目规则处理提交范围，已获授权时主动提交并核对 SHA。已请求且授权的发版也要完成并核实。用进度消息告知发现和下一步，然后继续执行。
- 确认存在未满足的验收条件时，直接执行下文的修复和复验流程。只有遇到需要用户决策、执行环境不可用等实际阻塞，才能按现有证据交回未完成项。
- 只读分析、方案审查或明确要求保留未提交改动的任务，以用户指定的交付条件为准。

## 开始前

1. 用 `workspace_list` 确认授权项目。用返回的目录名称作为 `workspace`，在该目录内读取项目规范和相关代码。接手已有任务时，先查 `execution_list` 并确认原任务、运行状态、验收记录和 Git 状态。
2. Git 项目在首次改动前用 `command_exec` 检查当前分支、`HEAD`、工作树及暂存区。保留任务前的改动。把验收条件写成能执行的命令或能观察的结果。
3. 优先遵从用户对执行者的指定。小而明确的修改由调用者执行并请 Codex 复审。复杂改动和根因排查交给 Codex，调用者先确定方案。单纯审查只返回经过确认的结论。第一次委派前读取 [CloudMCP 调用说明](references/cloudmcp.md)。

## 调用者实现，Codex 复审

调用者直接修改的内容，包括代码、文档和配置，必须交给 Codex 审查后才能报告完成。调用者用 `fs_read` 行模式定位、用 `fs_edit` 精确修改，并复跑当前环境支持的检查。用 `codex_exec` 新开审查会话，选择 `delegation="review"`，给出相关 diff 范围、改动理由和实际检查结果。逐项核对审查意见，记录采纳、部分采纳或拒绝的决定和证据。有未解决的问题时为该轮记录 `needs_work`。修复后重新验证，涉及实质修改时在同一审查会话（传原 `session_id`、新 `request_id`）请 Codex 复审修改后的 diff。验收通过时记录 `completed`，再由调用者收尾。

- 审查 brief 写明调用者环境的验证缺项，由审查轮完成适用的只读检查。因工具链或沙箱限制无法运行的必要检查，按 [CloudMCP 调用说明](references/cloudmcp.md) 的验证限制另行安排，由调用者核对结果。最终报告写明每项检查的执行者、环境和结果，未运行的列为待验证。
- 审查轮次要收敛：初审计为第 1 轮。经调用者核实的高、中风险问题须修复并复审；低风险问题可修复，或记录不采纳的理由。第 3 轮结束时仍有未解决的中高风险问题，记为 `needs_work`，暂停并交用户决定。

## Codex 实现，调用者验收

1. 用 `codex_exec` 发起 `delegation="implement"`，给出目标、决定的方案、改动范围、风险和 `acceptance_criteria`。必要时先发 `delegation="review"` 调查或审查方案，调用者作出决定后在同一会话切到实现角色。
2. 用 `execution_wait` 等这一轮结束：仅在状态为 `starting` 或 `running` 时继续等待；遇到 `unknown` 先核实进程、日志和改动；`finished=true` 表示已确认终态，再用 `execution_get` 读结果和关键证据。Codex 实现的改动必须由调用者审查。调用者自己看实际 diff、复跑当前环境支持的验收检查并核查回归；无法运行的必要检查按验证限制另行安排。UI 交付要核实真实应用里的效果，验证受限时记录具体缺项。逐项处理 Codex 的方案疑虑和审查意见，保留决定及理由。
3. 验收失败时，先调用 `execution_review` 标记当前轮次 `needs_work`，记录失败证据和决定。**同一轮对话继续调用 `codex_exec`**，传原 `session_id`、新的 `request_id`、`delegation="implement"` 和明确的修复要求。等修复结束后复验实际结果。证据显示原方案有问题时，调用者先重新判断方案，再让 Codex 修复。
4. 验收通过时，调用 `execution_review` 标记 `completed`，记录实际验证、处理过的审查意见和证据路径。继续执行已授权的收尾步骤。

## 交付

验收通过后，由调用者执行已授权的提交。发版任务由调用者读取项目发布说明，再执行已授权的打标签、推送、发布或部署步骤。交给 Codex 的 brief 只包含实现、调查、审查和验证。提交或发版前读取 [交付说明](references/delivery.md)，并核对任务基线和结果。

最后报告实际修改、独立验证结果、返工或复审结果、未采纳的重要意见及理由，以及实际提交的 SHA 和已核实的发布结果。遇到阻塞时写明已经完成的工作和缺少的条件。
